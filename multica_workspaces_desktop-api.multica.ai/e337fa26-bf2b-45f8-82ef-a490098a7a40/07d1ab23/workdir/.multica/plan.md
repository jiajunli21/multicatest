# Todo 任务管理系统 — 阶段计划文档

## 1. 需求目标

构建一个 Todo 任务管理系统，提供任务的全生命周期管理能力。用户可以通过该系统创建、查看、更新和删除任务，实现对日常工作任务的基本管理。

## 2. 功能范围

### 2.1 核心功能

| 功能 | 描述 |
|------|------|
| 创建任务 | 用户输入任务标题和可选的描述信息，系统生成一条新任务记录 |
| 查询任务列表 | 用户可查看所有任务，支持按状态筛选（待办 / 进行中 / 已完成） |
| 查询任务详情 | 用户点击某个任务，查看其完整信息（标题、描述、状态、创建/更新时间） |
| 更新任务状态 | 用户可修改任务状态：待办 → 进行中 → 已完成，支持任意方向流转 |
| 删除任务 | 用户可删除单个任务，系统执行软删除或硬删除 |

### 2.2 数据字段

每条任务至少包含：

- 唯一标识（id）
- 标题（title）
- 描述（description，可选）
- 状态（status）
- 创建时间（created_at）
- 更新时间（updated_at）

## 3. 非目标

以下内容**不在**本次实现范围内：

- 用户认证与授权系统（多用户、登录、权限控制）
- 任务分类/标签/优先级管理
- 任务截止日期与提醒通知
- 任务排序/搜索/分页（初次可全量返回）
- 任务分配（指派给多个用户）
- 子任务/任务依赖关系
- 批量操作（批量删除、批量状态变更）
- 数据持久化以外的持久层选择（直接使用合适的数据库即可，不做多数据库适配）
- 前端 UI 界面（本流水线聚焦后端 API）
- 国际化/多语言支持
- 文件附件上传

## 4. 核心业务流程

### 4.1 创建任务

```
用户 → POST /todos { title, description? } → 校验输入 → 生成任务（status=待办） → 返回任务对象
```

- title 必填，非空字符串，长度 1–255
- description 可选，最大 2000 字符
- 初始状态固定为"待办"
- 自动生成 id 和 created_at/updated_at 时间戳

### 4.2 查询任务列表

```
用户 → GET /todos?status={status} → 查询 → 返回任务列表
```

- 无 status 参数时返回全部任务
- status 参数可选值：`pending` / `in_progress` / `done`
- 默认按 created_at 倒序排列

### 4.3 查询任务详情

```
用户 → GET /todos/{id} → 按 id 查询 → 找到则返回任务对象，未找到则返回 404
```

### 4.4 更新任务状态

```
用户 → PATCH /todos/{id}/status { status } → 校验 id 存在 → 校验状态值合法 → 更新状态和 updated_at → 返回更新后的任务
```

- 允许的状态值：`pending` / `in_progress` / `done`
- 不限制状态流转方向（允许 pending→done、done→pending 等）
- 任务不存在时返回 404

### 4.5 删除任务

```
用户 → DELETE /todos/{id} → 按 id 查找 → 存在则删除 → 返回 204，不存在则返回 404
```

## 5. 领域对象

### 5.1 Task（任务）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | string/uuid | 是 | 全局唯一标识 |
| title | string(1-255) | 是 | 任务标题 |
| description | string(0-2000) | 否 | 任务描述 |
| status | enum | 是 | pending / in_progress / done |
| created_at | datetime | 是 | 创建时间（UTC） |
| updated_at | datetime | 是 | 最后更新时间（UTC） |

### 5.2 TaskStatus（任务状态枚举）

| 值 | 含义 |
|----|------|
| `pending` | 待办 |
| `in_progress` | 进行中 |
| `done` | 已完成 |

## 7. 测试关注点

### 7.1 单元测试

- 状态流转逻辑：验证任意合法状态转换均可执行
- 输入校验：空 title、超长 title、非法 status 值、超长 description
- 边界值：title 长度 1 / 255、description 长度 0 / 2000

### 7.2 集成测试 / API 测试

- 创建任务：正常创建，title 缺失返回 400
- 查询列表：全量查询、按状态筛选、空列表
- 查询详情：存在的 id 返回 200、不存在的 id 返回 404
- 更新状态：合法状态返回 200、非法状态返回 400、不存在的 id 返回 404
- 删除任务：存在的 id 返回 204、不存在的 id 返回 404、重复删除返回 404
- 并发安全：同一任务的并发更新不会导致数据损坏

### 7.3 数据完整性

- 创建任务后立即查询可获取到该任务
- 更新后 updated_at 大于 created_at
- 删除后查询该 id 返回 404

## 8. 风险与边界情况

### 8.1 技术风险

| 风险 | 等级 | 缓解措施 |
|------|------|---------|
| 数据库选型未确定 | 低 | 使用轻量级 SQLite 或内存数据库，后续可替换 |
| 无分页导致数据量过大 | 低 | 当前为 demo 系统，数据量可控；后续可加 offset/limit |
| 并发更新冲突 | 低 | 单用户 demo 场景概率极低；如需处理，可使用乐观锁 |

### 8.2 边界情况

- **空 title**：返回 400，附带明确错误信息
- **title 仅含空格**：应视为无效输入，返回 400
- **非法 status 值**：返回 400，列出合法值
- **id 格式不匹配**：返回 400（如传入非 UUID 格式字符串）
- **删除不存在的任务**：返回 404
- **重复删除**：第二次删除返回 404（幂等性通过 404 表达）
- **并发删除+查询**：删除后查询返回 404
- **超大 description**：超过 2000 字符返回 400

### 8.3 决策点（由下游阶段决定）

以下设计决策不在本阶段确定，交由架构和接口阶段处理：

- 数据库选型（SQLite / PostgreSQL / MySQL）
- 软删除 vs 硬删除
- id 生成策略（UUID v4 / 自增整数 / ULID）
- API 路径与版本前缀（/api/v1/...）
- 错误响应格式 (RFC 7807 / 自定义结构)
- 数据存储层的 ORM 选型
- 服务器框架选型（Express / FastAPI / Gin 等）
