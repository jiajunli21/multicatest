# Todo 任务管理系统 —— 阶段计划文档

## 需求目标

构建一个 Todo 任务管理系统，提供任务的完整生命周期管理能力，包括创建、查询（列表/详情）、状态更新和删除。

## 功能范围

### 核心功能

| 编号 | 功能 | 描述 |
|------|------|------|
| F1 | 创建任务 | 用户可创建一个新任务，包含标题、描述、优先级等基本信息 |
| F2 | 查询任务列表 | 用户可获取任务列表，支持按状态/优先级筛选和分页 |
| F3 | 查询任务详情 | 用户可根据任务 ID 获取单个任务的完整信息 |
| F4 | 更新任务状态 | 用户可修改任务的状态（如待办 → 进行中 → 已完成） |
| F5 | 删除任务 | 用户可删除一个任务（软删除或硬删除，由架构阶段决策） |

### 辅助功能

- 任务支持优先级标记（低/中/高）
- 任务列表支持基本筛选和排序
- 统一的错误响应格式

## 非目标

以下内容明确不在本期范围：

- 用户认证与授权体系（多用户、登录/注册）
- 任务分配（指派给特定用户）
- 任务标签/分类体系
- 任务截止日期提醒与通知
- 任务评论/协作功能
- 任务附件上传
- 任务历史/操作日志
- 实时协作/WebSocket 推送
- 前端 UI 具体实现（仅提供 API 契约供前端参考）

## 核心业务流程

### 1. 创建任务

```
用户输入(title, description?, priority?) → 校验 → 生成任务 → 返回任务详情
```

### 2. 查询任务列表

```
请求(筛选条件?, 分页参数?) → 查询 → 返回分页列表
```

### 3. 查询任务详情

```
请求(taskId) → 查询 → 存在则返回详情, 不存在则返回 404
```

### 4. 更新任务状态

```
请求(taskId, newStatus) → 校验状态流转合法性 → 更新 → 返回更新后详情
```

### 5. 删除任务

```
请求(taskId) → 查询 → 存在则删除, 不存在则返回 404
```

## 领域对象

### Task（任务）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | string(uuid) | 是 | 任务唯一标识 |
| title | string | 是 | 任务标题，长度 1-200 |
| description | string | 否 | 任务描述，最大 2000 字符 |
| status | enum | 是 | 任务状态 |
| priority | enum | 否 | 优先级，默认 MEDIUM |
| created_at | datetime | 是 | 创建时间 |
| updated_at | datetime | 是 | 最后更新时间 |

### TaskStatus（任务状态枚举）

| 值 | 说明 |
|------|------|
| TODO | 待办 |
| IN_PROGRESS | 进行中 |
| DONE | 已完成 |

### TaskPriority（任务优先级枚举）

| 值 | 说明 |
|------|------|
| LOW | 低 |
| MEDIUM | 中 |
| HIGH | 高 |

### 状态流转规则

```
TODO → IN_PROGRESS → DONE
TODO → DONE (允许直接完成)
IN_PROGRESS → TODO (允许退回)
DONE → IN_PROGRESS (允许重新打开)
```

- 不允许从 DONE 直接到 TODO（需经过 IN_PROGRESS）
- 不允许从不存在的状态流转

### 分页对象

| 字段 | 类型 | 说明 |
|------|------|------|
| items | Task[] | 当前页任务列表 |
| total | number | 总任务数 |
| page | number | 当前页码 |
| page_size | number | 每页条数 |

## 前后端任务拆分建议

### 后端任务

1. **数据层**：设计 Task 数据库表/Schema，包含字段定义、索引和约束
2. **API 层**：实现 RESTful 接口（创建、查询、更新、删除）
3. **业务逻辑层**：状态流转校验、参数校验、错误处理
4. **测试**：单元测试覆盖 Service 层，集成测试覆盖 API 端点

### 前端任务

1. 任务列表页面（含筛选、分页）
2. 任务创建表单/弹窗
3. 任务详情页面
4. 状态更新交互（下拉/拖拽）
5. 删除确认交互
6. API 错误处理与提示

**决策留白**：前后端是否同仓库、前端技术栈由后续团队决定，本计划不做约束。

## 测试关注点

### 单元测试

- TaskService 各方法逻辑正确性
- 状态流转校验（合法/非法流转）
- 输入参数校验（空标题、超长字段等）

### 集成测试

- 创建任务 → 返回正确数据 → 可查询到
- 更新任务状态 → 验证状态流转
- 删除任务 → 确认不可再查询
- 查询不存在任务 → 返回 404
- 分页参数边界（page=0, page_size=0, page_size=MAX）

### 边界测试

- 并发更新同一任务
- 重复删除同一任务（幂等性）
- 标题为空字符串
- 超大 page_size

## 风险与边界情况

### 风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 未定义用户体系，后续扩展需重构 | 中 | 预留 user_id 字段但本期不启用，避免数据库迁移困难 |
| 状态流转规则变化 | 低 | 状态机集中管理，新增状态只需扩展枚举和流转表 |
| 并发更新导致数据不一致 | 中 | 使用乐观锁（version 字段）或数据库行锁 |

### 边界情况

- 空列表查询：返回 items=[], total=0，不报错
- 删除已删除的任务：返回 404 或 204（幂等处理）
- 超长输入：返回 400 并给出明确错误信息
- 非法状态值：返回 400 并列出合法状态值
- JSON 格式错误：返回 400 并提示格式问题
