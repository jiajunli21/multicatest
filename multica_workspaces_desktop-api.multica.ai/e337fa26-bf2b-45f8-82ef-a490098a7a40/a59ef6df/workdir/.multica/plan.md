# Todo 任务管理系统 —— 阶段计划文档

## 需求目标

构建一个 Todo 任务管理系统，提供任务的完整生命周期管理能力，支持创建任务、查询任务列表、查询任务详情、更新任务状态和删除任务。

## 功能范围

### 核心功能

| 编号 | 功能 | 描述 |
|------|------|------|
| F1 | 创建任务 | 用户创建一个新任务，包含标题、描述、优先级等基本信息 |
| F2 | 查询任务列表 | 获取任务列表，支持按状态/优先级筛选和分页 |
| F3 | 查询任务详情 | 根据任务 ID 获取单个任务的完整信息 |
| F4 | 更新任务状态 | 修改任务的状态（待办 → 进行中 → 已完成，支持退回） |
| F5 | 删除任务 | 删除一个任务（软删除或硬删除，由架构阶段决策） |

### 辅助特性

- 任务支持优先级标记（低/中/高）
- 任务列表支持基本筛选（状态、优先级）和排序
- 统一的错误响应格式

## 非目标

以下内容明确不在本期范围：

- 用户认证与授权体系（多用户、登录/注册）
- 任务分配（指派给特定用户）
- 任务标签/分类体系
- 任务截止日期提醒与通知
- 任务评论/协作功能
- 任务附件上传
- 任务历史/操作日志
- 实时协作/WebSocket 推送
- 前端 UI 具体实现（仅提供 API 契约供前端参考）

## 核心业务流程

### 1. 创建任务

```
用户输入(title, description?, priority?) → 参数校验 → 生成任务 → 返回任务详情(201)
```

### 2. 查询任务列表

```
请求(status?, priority?, page?, page_size?, sort?) → 查询 → 返回分页列表(200)
```

### 3. 查询任务详情

```
请求(taskId) → 查询 → 存在返回详情(200), 不存在返回(404)
```

### 4. 更新任务状态

```
请求(taskId, newStatus) → 校验状态流转合法性 → 更新 → 返回更新后详情(200)
```

### 5. 删除任务

```
请求(taskId) → 查询 → 存在则删除(200/204), 不存在返回(404)
```

## 领域对象

### Task（任务）

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| id | string(uuid) | 是 | 自动生成 | 任务唯一标识 |
| title | string | 是 | - | 任务标题，长度 1-200 |
| description | string | 否 | "" | 任务描述，最大 2000 字符 |
| status | TaskStatus | 是 | TODO | 任务状态 |
| priority | TaskPriority | 否 | MEDIUM | 优先级 |
| created_at | datetime | 是 | 自动生成 | 创建时间 |
| updated_at | datetime | 是 | 自动更新 | 最后更新时间 |

### TaskStatus（任务状态枚举）

| 值 | 说明 |
|------|------|
| TODO | 待办 |
| IN_PROGRESS | 进行中 |
| DONE | 已完成 |

### TaskPriority（任务优先级枚举）

| 值 | 说明 |
|------|------|
| LOW | 低 |
| MEDIUM | 中（默认） |
| HIGH | 高 |

### 状态流转规则

```
TODO → IN_PROGRESS → DONE
TODO → DONE            (允许直接完成，跳过进行中)
IN_PROGRESS → TODO     (允许退回到待办)
DONE → IN_PROGRESS     (允许重新打开)
```

禁止的流转：
- DONE → TODO（需经过 IN_PROGRESS）
- 到不存在的状态值
- 同状态不变更新（可返回 200 不修改或 400 拒绝，由接口阶段决策）

### 分页对象

| 字段 | 类型 | 说明 |
|------|------|------|
| items | Task[] | 当前页任务列表 |
| total | number | 总任务数 |
| page | number | 当前页码（从 1 开始） |
| page_size | number | 每页条数 |

## 前后端任务拆分建议

### 后端任务

1. **数据层**：设计 Task 数据库表/Schema，包含字段定义、索引和约束
2. **API 层**：实现 RESTful 接口（创建、查询列表、查询详情、更新状态、删除）
3. **业务逻辑层**：状态流转校验、参数校验、错误处理、分页逻辑
4. **测试**：单元测试覆盖 Service 层核心逻辑，集成测试覆盖 API 端点

### 前端任务

1. 任务列表页面（含状态/优先级筛选、分页、排序）
2. 任务创建表单/弹窗
3. 任务详情页面
4. 状态更新交互（下拉/拖拽/按钮）
5. 删除确认交互
6. API 错误处理与用户提示

**决策留白**：前后端是否同仓库、前端技术栈由后续团队决定，本计划不做约束。

## 测试关注点

### 单元测试

- TaskService 各方法逻辑正确性
- 状态流转校验（合法流转通过、非法流转拒绝）
- 输入参数校验（空标题、超长字段、非法枚举值）
- 分页参数处理（默认值、边界值）

### 集成测试

- 创建任务 → 返回 201 + 正确数据 → 可后续查询到
- 更新任务状态 → 验证状态流转规则全部路径
- 删除任务 → 确认删除后不可再查询
- 查询不存在任务 → 返回 404
- 分页参数边界（page=0, page=-1, page_size=0, page_size=超大值）
- 筛选条件组合（状态+优先级）

### 边界与异常测试

- 并发更新同一任务的数据一致性
- 重复删除同一任务（幂等性处理）
- 标题为空字符串或纯空白
- 请求体 JSON 格式错误
- 请求体包含未知字段
- 超大 page_size 导致性能问题

## 风险与边界情况

### 风险

| 风险 | 影响等级 | 缓解措施 |
|------|----------|----------|
| 未定义用户体系，后续多用户扩展需重构 | 中 | 预留 user_id 字段但本期不启用，数据表设计时考虑扩展性 |
| 状态流转规则未来变化 | 低 | 状态机逻辑集中管理，新增状态只需扩展枚举和流转规则表 |
| 并发更新导致数据不一致 | 中 | 使用乐观锁（version 字段）或数据库行级锁 |
| 无持久化存储选型约束，后期迁移成本 | 低 | 数据访问层抽象，不绑定具体存储实现 |

### 边界情况

- 空列表查询：返回 items=[], total=0，状态码 200
- 删除已删除的任务：返回 404 或 204（幂等处理，由架构阶段决策）
- 超长输入：返回 400，并给出字段名和长度限制
- 非法状态值：返回 400，并列出合法状态值
- JSON 格式错误：返回 400，提示格式问题
- page 超出实际页数：返回空列表 items=[]
