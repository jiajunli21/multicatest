# Todo 任务管理系统 —— 阶段计划文档

## 1. 需求目标

构建一个 Todo 任务管理系统，为用户提供任务的完整生命周期管理能力，覆盖任务的创建、查询、状态更新与删除。

系统定位为单用户工具，聚焦核心任务管理流程，不涉及多用户协作、权限控制或消息通知。

## 2. 功能范围

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 创建任务 | 用户输入任务标题、描述、优先级等信息，系统创建并返回任务 | P0 |
| 查询任务列表 | 支持分页查询，可按状态、优先级筛选，按创建时间排序 | P0 |
| 查询任务详情 | 根据任务 ID 返回任务的完整信息 | P0 |
| 更新任务状态 | 修改指定任务的状态，需校验状态流转合法性 | P0 |
| 删除任务 | 删除指定任务（软删除，保留数据可追溯） | P0 |

### 任务字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | string (UUID) | 自动生成 | 任务唯一标识 |
| title | string | 是 | 任务标题，1-200 字符 |
| description | string | 否 | 任务描述，最大 2000 字符 |
| status | enum | 自动设置 | 任务状态，新建默认 `todo` |
| priority | enum | 否 | 优先级，默认 `medium` |
| created_at | timestamp | 自动设置 | 创建时间 |
| updated_at | timestamp | 自动设置 | 最后更新时间 |
| deleted_at | timestamp | 否 | 软删除时间，为空表示未删除 |

### 状态枚举

| 状态 | 说明 |
|------|------|
| `todo` | 待处理 |
| `in_progress` | 进行中 |
| `done` | 已完成 |
| `cancelled` | 已取消 |

### 优先级枚举

| 优先级 | 说明 |
|------|------|
| `low` | 低 |
| `medium` | 中 |
| `high` | 高 |

## 3. 非目标

以下功能明确排除在本期范围之外：

- **用户认证与授权**：无登录、注册、权限控制
- **多用户协作**：任务无归属、无分配、无共享
- **到期提醒与通知**：无邮件、推送或站内通知
- **标签/分类/项目分组**：任务无多级分类
- **子任务/任务依赖**：任务之间无层级或依赖关系
- **文件附件**：不支持上传附件
- **评论/活动日志**：无操作历史审计
- **批量操作**：不支持批量创建、更新或删除
- **搜索与全文检索**：仅支持按状态、优先级筛选，不做关键词搜索
- **国际化/多语言**：仅支持中文

## 4. 核心业务流程

### 4.1 创建任务

```
用户提供 title（必填）、description（可选）、priority（可选）
    → 系统校验输入合法性
        - title 非空，1-200 字符
        - description 最大 2000 字符
        - priority 值有效（low / medium / high）
    → 系统生成 UUID 作为 id
    → 设置 status = "todo"
    → 记录 created_at、updated_at
    → 持久化存储
    → 返回创建的任务对象
```

**校验失败处理**：返回 400 错误及具体校验失败原因。

### 4.2 查询任务列表

```
用户请求列表（可选参数：status、priority、page、page_size）
    → 系统校验分页参数
        - page >= 1，默认 1
        - page_size 1-100，默认 20
    → 按条件过滤：
        - status 匹配（精确匹配）
        - priority 匹配（精确匹配）
    → 排除已软删除任务（deleted_at IS NOT NULL）
    → 按 created_at 降序排列
    → 分页查询
    → 返回任务列表 + 分页信息（total、page、page_size）
```

**空列表处理**：返回空数组和 total=0，不是错误。

### 4.3 查询任务详情

```
用户提供任务 ID
    → 系统按 ID 查询
    → 任务不存在 → 返回 404
    → 任务已软删除 → 返回 404
    → 返回完整任务信息
```

### 4.4 更新任务状态

```
用户提供任务 ID 和新状态
    → 系统按 ID 查询
    → 任务不存在 → 返回 404
    → 任务已软删除 → 返回 404
    → 校验状态值有效（todo / in_progress / done / cancelled）
        - 无效状态 → 返回 400
    → 校验状态流转合法性（见下方流转规则）
        - 不合法流转 → 返回 400 并说明原因
    → 更新 status 和 updated_at
    → 返回更新后的任务对象
```

**状态流转规则**：

```
todo ────────→ in_progress
todo ────────→ cancelled
in_progress ─→ done
in_progress ─→ cancelled
done ────────→ (不可流转)
cancelled ───→ (不可流转)
```

- `done` 和 `cancelled` 为终态，不可再变更
- 不允许跳过中间状态（如 `todo` → `done`）
- 不支持逆流转（如 `done` → `in_progress`）

### 4.5 删除任务

```
用户提供任务 ID
    → 系统按 ID 查询
    → 任务不存在或已软删除 → 返回 404
    → 设置 deleted_at = 当前时间
    → 返回成功响应（无内容或确认信息）
```

- 使用软删除：数据库记录保留，通过 `deleted_at` 标记
- 删除后任务不可通过列表或详情接口查询
- 本期不提供恢复已删除任务的功能

## 5. 领域对象

### 核心实体：Task

```
Task {
    id:          UUID          // 主键
    title:       string        // 任务标题
    description: string|null   // 任务描述
    status:      TaskStatus    // 任务状态
    priority:    TaskPriority  // 优先级
    created_at:  timestamp     // 创建时间
    updated_at:  timestamp     // 更新时间
    deleted_at:  timestamp|null // 软删除时间
}
```

### 值对象

```
TaskStatus:    "todo" | "in_progress" | "done" | "cancelled"
TaskPriority:  "low" | "medium" | "high"
```

### 聚合

单聚合根 `Task`，不依赖其他实体。

## 6. 前后端任务拆分建议

### 后端任务

| 任务 | 说明 |
|------|------|
| 数据库 Schema 设计 | 定义 Task 表结构、索引（status、deleted_at） |
| API 契约定义 | 5 个 REST 端点的请求/响应结构 |
| Controller 层 | 路由、请求参数校验、响应格式化 |
| Service 层 | 业务逻辑：状态流转校验、CRUD 编排 |
| Repository 层 | 数据持久化：增删改查、分页、过滤 |
| 错误处理与统一响应 | 错误码定义、全局异常处理、统一响应格式 |
| 集成测试 | API 端点测试、状态流转边界测试 |

### 前端任务

| 任务 | 说明 |
|------|------|
| 任务列表页 | 展示任务列表、分页、状态/优先级筛选 |
| 任务创建表单 | 输入标题、描述、优先级，提交创建 |
| 任务详情页/弹窗 | 展示任务完整信息 |
| 任务状态更新 | 下拉或按钮切换任务状态 |
| 任务删除 | 删除确认，调用删除接口 |
| API 请求封装 | 统一请求/响应处理、错误提示 |
| 组件测试 | 关键交互的冒烟测试 |

### 建议开发顺序

1. 后端：Schema → API 契约 → Repository → Service → Controller
2. 前端：API 封装 → 任务列表 → 创建表单 → 详情 → 状态更新 → 删除

## 7. 测试关注点

### 单元测试

- Service 层状态流转规则：每种合法/非法流转组合
- 输入校验逻辑：title 长度边界、description 长度边界、无效 priority
- 分页参数校验：page=0、page_size=101 等边界值

### 集成测试

- 创建任务：正常创建、缺少必填字段、字段超长
- 查询列表：空列表、单页、多页、按状态筛选、按优先级筛选、组合筛选
- 查询详情：正常查询、不存在的 ID、UUID 格式错误
- 更新状态：合法流转（todo→in_progress 等）、非法流转（todo→done、done→任意）、终态操作
- 删除：正常删除、重复删除（幂等性）、删除后查询

### 边界场景

- 并发更新同一任务的状态
- 请求体包含未知字段时的处理
- 超长字符串输入
- 空请求体
- 特殊字符/emoji 在 title 和 description 中

## 8. 风险与边界情况

| 风险/边界 | 说明 | 建议处理 |
|------|------|---------|
| 状态流转规则变更 | 未来可能需要更灵活的状态机 | 当前采用硬编码流转表，后续可配置化 |
| 数据量增长 | 任务数量增加导致列表查询变慢 | 数据库加索引（status、deleted_at、created_at），业务层强制分页 |
| 并发冲突 | 多请求同时更新同一任务 | 本期不做乐观锁，依赖数据库行级锁，后续可引入 version 字段 |
| 软删除数据膨胀 | 长期运行后已删除数据占比高 | 本期不做处理，后续可增加定期清理机制 |
| 输入注入风险 | title/description 可能包含 XSS 内容 | 后端存储原始值不做过滤，前端渲染时做转义 |
| UUID 碰撞 | UUID v4 极小概率会重复 | 数据库层加唯一约束，插入冲突时重试生成 |
| API 版本兼容 | 未来接口变更需向后兼容 | 建议在 API path 中预留版本前缀（如 `/api/v1/tasks`） |
