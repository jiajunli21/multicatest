# Todo 任务管理系统 — 阶段计划文档

## 需求目标

构建一个 Todo 任务管理系统，提供任务的完整生命周期管理能力，支持：

- 创建新任务
- 查询任务列表（支持分页、筛选）
- 查询任务详情
- 更新任务状态
- 删除任务

目标用户为普通终端用户，交互方式为 RESTful API，数据持久化存储。

## 功能范围

### P0（必须实现）

| 功能 | 描述 |
|------|------|
| 创建任务 | 接受任务标题（必填）和描述（可选），返回创建的任务对象，自动分配唯一 ID、创建时间戳，初始状态为 `todo` |
| 查询任务列表 | 分页查询所有任务，支持按状态筛选（`todo` / `in_progress` / `done`），按创建时间倒序排列 |
| 查询任务详情 | 按 ID 查询单个任务完整信息，ID 不存在时返回 404 |
| 更新任务状态 | 按 ID 更新任务状态，支持 `todo` → `in_progress` → `done` 及逆向流转 |
| 删除任务 | 按 ID 删除任务（硬删除），ID 不存在时返回 404 |

### P1（建议实现，非本阶段硬性要求）

- 任务编辑：更新标题和描述
- 按优先级排序
- 任务搜索：按标题关键词模糊搜索

## 非目标

以下明确不在当前版本范围内：

- 用户认证与多租户隔离
- 任务分配给多用户
- 任务截止日期与提醒通知
- 子任务 / 任务层级
- 任务标签 / 分类体系
- 任务评论与协作
- 批量操作（批量删除、批量状态更新）
- 软删除与回收站
- 数据导入导出
- 实时协作（WebSocket）

## 核心业务流程

### 1. 创建任务

```
用户 → POST /todos { title, description? }
     → 校验 title 非空、长度 ≤ 200
     → 生成 ID（UUID）
     → 设置 status = "todo"
     → 记录 created_at、updated_at
     → 持久化
     → 返回 201 + Task 对象
```

### 2. 查询任务列表

```
用户 → GET /todos?status={status}&page={page}&size={size}
     → 校验参数（page ≥ 1, size 1–100, status 合法枚举或空）
     → 查询数据库（按条件筛选、分页、按 created_at DESC 排序）
     → 返回 200 + { items: Task[], total: number, page: number, size: number }
```

### 3. 查询任务详情

```
用户 → GET /todos/{id}
     → 校验 ID 格式（UUID）
     → 查询数据库
     → 存在：返回 200 + Task 对象
     → 不存在：返回 404
```

### 4. 更新任务状态

```
用户 → PATCH /todos/{id}/status { status: "in_progress" | "done" | "todo" }
     → 校验 ID 格式
     → 校验 status 值合法
     → 查询数据库
     → 不存在：返回 404
     → 存在：更新 status 和 updated_at
     → 返回 200 + 更新后的 Task 对象
```

### 5. 删除任务

```
用户 → DELETE /todos/{id}
     → 校验 ID 格式
     → 查询数据库
     → 不存在：返回 404
     → 存在：执行硬删除
     → 返回 204 No Content
```

## 领域对象

### Task（任务）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | UUID (string) | 是 | 唯一标识，服务端生成 |
| title | string (1-200) | 是 | 任务标题 |
| description | string (0-5000) | 否 | 任务描述，可为空 |
| status | enum | 是 | `todo` / `in_progress` / `done`，默认 `todo` |
| created_at | ISO8601 timestamp | 是 | 创建时间，服务端生成 |
| updated_at | ISO8601 timestamp | 是 | 最近更新时间，服务端生成 |

### 状态流转规则

```
todo ──────→ in_progress ──────→ done
  ↑               │                 │
  └───────────────┴─────────────────┘
         (允许任意逆向流转)
```

- 允许 `done` → `todo`（重新打开）
- 允许 `done` → `in_progress`
- 允许 `in_progress` → `todo`（退回）
- 不允许无效状态值

### 查询参数对象

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| status | enum? | 否 | 筛选条件，不传则为全部 |
| page | int (≥1) | 否 | 页码，默认 1 |
| size | int (1-100) | 否 | 每页条数，默认 20 |

### 决策点

- **框架选型**：由 BEW-5 阶段根据项目现有技术栈决定
- **数据库选型**：由 BEW-3 阶段决定（SQLite / PostgreSQL / MySQL）
- **分页策略**：推荐 offset-based 分页，本期不做 cursor-based
- **ID 策略**：推荐 UUIDv4，由服务端生成
- **状态流转是否需要后端强校验**：是，必须在 Service 层校验状态流转合法性

## 测试关注点

### 单元测试

| 测试对象 | 关注点 |
|----------|--------|
| Service 层 | 状态流转规则校验、参数合法性 |
| 参数校验器 | title 非空/长度、status 枚举值、分页参数范围 |

### 集成测试 / API 测试

| 场景 | 关注点 |
|------|--------|
| 创建任务 | 必填字段缺失返回 400、创建成功后字段完整性 |
| 查询列表 | 无数据返回空列表、分页边界、状态筛选准确性、排序正确性 |
| 查询详情 | 存在的 ID 返回完整对象、不存在的 ID 返回 404 |
| 更新状态 | 合法状态流转成功、非法状态值返回 400、不存在的 ID 返回 404 |
| 删除任务 | 存在的 ID 删除成功返回 204、不存在的 ID 返回 404、删除后再次查询返回 404 |
| 并发 | 同时更新同一任务状态无数据错乱 |
| 边界 | title=1 字符、title=200 字符、description=5000 字符 |

### 端到端测试

- 完整用户流程：创建 → 查看列表 → 查看详情 → 更新状态 → 删除 → 确认删除

## 风险与边界情况

### 风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 数据库不可用 | 全部接口 5xx | 连接池配置、健康检查端点 |
| 并发状态更新 | 状态不一致 | 乐观锁或数据库事务 |
| UUID 碰撞 | 创建失败 | UUIDv4 碰撞概率极低，可接受 |
| title 国际化字符 | 校验/存储异常 | UTF-8 编码，字符数按 rune 而非 byte 计算 |

### 边界情况

| 场景 | 预期行为 |
|------|----------|
| 任务列表无数据 | 返回空 items，total=0 |
| page 超出范围 | 返回空列表，非错误 |
| size=0 | 返回 400 参数校验失败 |
| title 为空字符串 | 返回 400 |
| title 仅为空白字符 | 返回 400（trim 后校验） |
| description 为空字符串 | 允许，视为无描述 |
| 更新状态为当前相同状态 | 允许（幂等），updated_at 更新 |
| 多个请求同时删除同一 ID | 第一个返回 204，后续返回 404 |
| 请求体包含未定义字段 | 忽略额外字段 |
