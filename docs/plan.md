# Todo 任务管理系统 —— 阶段计划文档

## 1. 需求目标

构建一个 Todo 任务管理系统，提供任务的完整生命周期管理能力，包括任务的创建、查询、状态更新与删除。系统面向通用任务管理场景，要求接口清晰、数据一致、易于扩展。

核心目标：
- 用户可以创建待办任务，记录任务基本信息
- 用户可以按条件查询任务列表，支持基本筛选
- 用户可以查看单个任务的完整详情
- 用户可以更新任务状态，反映任务进展
- 用户可以删除不再需要的任务

## 2. 功能范围

### 2.1 任务创建
- 创建一个新任务，至少包含标题（title）和状态（status）
- 可选字段：描述（description）、优先级（priority）、截止日期（due_date）
- 创建时自动分配唯一 ID 和创建时间戳

### 2.2 任务列表查询
- 返回所有任务的分页列表
- 支持按状态筛选（如：待办、进行中、已完成）
- 支持按优先级筛选
- 列表项返回任务摘要信息（ID、标题、状态、优先级、创建时间）

### 2.3 任务详情查询
- 根据任务 ID 返回完整任务信息
- 包含所有字段：ID、标题、描述、状态、优先级、截止日期、创建时间、更新时间

### 2.4 任务状态更新
- 支持更新任务状态（todo / in_progress / done）
- 支持更新任务的其他字段（标题、描述、优先级、截止日期）
- 更新时自动刷新更新时间戳

### 2.5 任务删除
- 根据任务 ID 删除指定任务
- 删除为硬删除，不可恢复
- 删除不存在的任务应返回明确错误

## 3. 非目标

本次迭代明确不包含以下功能：
- **用户认证与多租户**：不区分用户，所有任务为全局共享
- **任务分配与协作**：不支持将任务分配给特定用户
- **子任务与任务依赖**：任务之间无层级或依赖关系
- **标签/分类系统**：不支持自定义标签或分类
- **搜索与全文检索**：仅支持按状态和优先级筛选，不支持关键词搜索
- **批量操作**：不支持批量创建、更新或删除
- **数据持久化方案选型**：存储方案由架构阶段决定，本阶段不绑定
- **前端 UI 实现**：本阶段只规划前后端边界，不设计具体 UI

## 4. 核心业务流程

### 4.1 创建任务流程
```
用户/前端 → POST /todos（携带 title + 可选字段）
         → 后端校验输入
         → 生成 ID 和时间戳
         → 持久化存储
         → 返回完整的任务对象（含 ID、时间戳）
```

### 4.2 查询任务列表流程
```
用户/前端 → GET /todos?status=xxx&priority=xxx&page=1&page_size=20
         → 后端解析查询参数
         → 按条件查询存储层
         → 返回分页结果（含总数、当前页数据）
```

### 4.3 查询任务详情流程
```
用户/前端 → GET /todos/:id
         → 后端校验 ID 格式
         → 按 ID 查询存储层
         → 存在则返回完整对象
         → 不存在则返回 404
```

### 4.4 更新任务状态流程
```
用户/前端 → PATCH /todos/:id（携带待更新字段）
         → 后端校验 ID 格式和输入
         → 按 ID 查找任务
         → 存在则更新指定字段并刷新 updated_at
         → 不存在则返回 404
         → 返回更新后的完整任务对象
```

### 4.5 删除任务流程
```
用户/前端 → DELETE /todos/:id
         → 后端校验 ID 格式
         → 按 ID 查找任务
         → 存在则删除并返回 204
         → 不存在则返回 404
```

## 5. 领域对象

### 5.1 Todo（核心领域对象）

| 字段          | 类型       | 必填 | 说明                                   |
|---------------|------------|------|----------------------------------------|
| id            | string/uuid| 是   | 唯一标识，创建时自动生成               |
| title         | string     | 是   | 任务标题，长度建议 1-200 字符          |
| description   | string     | 否   | 任务详细描述，长度建议 0-2000 字符     |
| status        | enum       | 是   | 任务状态，默认 todo                    |
| priority      | enum       | 否   | 优先级，默认 medium                    |
| due_date      | datetime   | 否   | 截止日期                               |
| created_at    | datetime   | 是   | 创建时间，自动生成                     |
| updated_at    | datetime   | 是   | 最后更新时间，自动维护                 |

### 5.2 状态枚举

| 值          | 说明       |
|-------------|------------|
| todo        | 待办       |
| in_progress | 进行中     |
| done        | 已完成     |

### 5.3 优先级枚举

| 值     | 说明   |
|--------|--------|
| low    | 低     |
| medium | 中     |
| high   | 高     |

### 5.4 状态流转规则

```
todo → in_progress → done
todo → done（允许跳过进行中直接完成）
in_progress → todo（允许回退到待办）
done → todo（允许重新打开已完成任务）
```

所有状态之间均可相互转换，不做强制流转限制，以保持灵活性。

## 7. 测试关注点

### 7.1 单元测试
- Service 层业务逻辑：状态转换、字段校验、ID 生成
- 输入校验：必填字段、字符串长度限制、枚举值合法性
- 边界条件：空标题、超长描述、非法状态值、不存在的 ID

### 7.2 集成测试
- 创建任务 → 查询详情 → 更新状态 → 删除任务的完整流程
- 分页查询：首页、末页、空页、越界页码
- 筛选查询：按状态筛选、按优先级筛选、组合筛选
- 并发场景：同一任务并发更新的最终一致性

### 7.3 边界测试
- 请求体缺失必填字段时的错误响应
- 请求包含未知字段时的行为
- 超长字符串输入的处理
- 删除已删除任务的幂等性
- 特殊字符在标题和描述中的处理

### 7.4 测试数据
- 使用固定的测试数据集，不依赖生产数据
- 每次测试前后清理数据，保证测试隔离

## 8. 风险与边界情况

### 8.1 风险
| 风险                     | 影响       | 缓解措施                               |
|--------------------------|------------|----------------------------------------|
| ID 冲突                   | 数据覆盖   | 使用 UUID 或数据库自增 ID，确保唯一性  |
| 并发更新导致数据不一致    | 数据丢失   | 使用乐观锁或数据库事务保障一致性       |
| 输入未校验导致脏数据      | 数据污染   | 后端对所有输入做严格校验，不信任前端   |
| 存储方案选择不当          | 扩展受限   | 通过接口抽象存储层，不绑定具体实现     |
| 无用户认证导致数据混杂    | 数据安全   | 文档明确标注为 V2 规划，当前接受此限制 |

### 8.2 边界情况
- **空列表查询**：无任务时返回空列表和 total=0，不报错
- **重复创建**：每次创建都生成新 ID，不判断重复（标题相同视为不同任务）
- **部分更新**：PATCH 只更新传入的字段，未传字段保持原值
- **时间戳精度**：统一使用 UTC 时间，精度到秒或毫秒
- **分页参数**：page 从 1 开始，page_size 默认 20，上限 100
- **错误响应格式**：统一使用 `{ "error": "message" }` 格式，配合合适的 HTTP 状态码
- **删除幂等性**：删除不存在的任务返回 404，重复删除同样返回 404
