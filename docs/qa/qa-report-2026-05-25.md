## 10. 发现的问题

### P1 — 接口契约 status 值不一致

| 接口 | 代码值 | 契约值 | 影响 |
|------|--------|--------|------|
| IA-005 | `ok` / `error` | `subscribed` / `unsubscribed` / `unchanged` | 前端需适配 status 字段 |
| IA-006 | `ok` / `error` / `no_subscribers` | `completed` / `partial` | 前端需适配 |
| IA-007 | `ok` | `success` / `partial` | 前端需适配 |

### P2 — 接口响应字段缺失

| 接口 | 缺失字段 | 说明 |
|------|----------|------|
| IA-006 | `total_subscribers`, `success_count`, `failed_users` | 代码用 `delivered_count`/`failed_count` 替代 |
| IA-007 | `group_name`, `total_count` | 代码未实现 |

### P2 — 契约文档路径不一致

- 契约文档 IA-007: `/add-to-watchlist` → 代码: `/watchlist/add` (与Leader映射表一致)
- 契约文档 IA-008: `/config/etf-samples` → 代码: `/config/etf-list` (与Leader映射表一致)

### P2 — Push fallback market_tag 污染

`push.ts:53/58` fallback 路径中 `marketTag` 包含状态标记字面量 `'[default] 谨慎参与'`，应仅为 `'谨慎参与'`

### P2 — DB Schema 与数据 Handoff 差异

数据 handoff 提及 `etf_labels`/`etf_factors`/`etf_daily_data`/`etf_rankings` 等多表，实际 DB 仅 `etf_scores` + `historical_records`。标签/因子/排名全部内嵌在 `etf_scores` 表中。功能无影响。
